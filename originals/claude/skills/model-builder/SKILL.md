# 재무모델 제작 표준 진입점 (진입 파일)

**정본은 `<모델링_세팅>\` 에 있다**(사용자가 Drive 로 옮긴 자리 — 2026-10-31 확인, 옮긴 자리가 정본). 이 파일은 진입용이고 본문은 거기 있다.
폴더가 없으면 사용자가 옮긴 것이다 → `<Drive>\`·`Downloads` 아래에서 `*모델링_세팅*` 을 찾아 쓰고, 찾으면 이 파일의 경로를 고친다.

```
<정본> = <모델링_세팅>\
  00_README_먼저읽기.md           ← 먼저 읽는다 (전체 지도, 사용법, 만든 것/안 만든 것)
  02_설계\01_아키타입_라우팅.md    ← 요청을 13개 유형(V-S·V-E·V-M·V-L·V-C·V-XL / P-JV·P-RE / O-PLT·O-CON·O-SM / X-SYN / D-BOOK)+상류 모듈 후보(I-TAM) 중 어느 것으로 볼지, 유형별 질문·자동수집·기본값
  02_설계\02_레퍼런스급_품질계약.md    ← 납품 조건 33개(QC-01~33) + 결함 레지스터 + 3관문
  02_설계\04_벤치마크_기본값.md    ← 샘플에서 뽑은 변수 범위 (입력값 아님, 시점 의존 값 사용 금지)
  02_설계\05_VXL_큐브생성기_설계.md ← 실사형(레퍼런스) 설계 (미구현)
  03_엔진\                         ← DCF 엔진 v2.1 (build_dcf.py, check_dcf.py, kmodel_common.py, inputs_template.yaml, tests\regress.py, CHANGELOG_v2.md)
  04_도구\lint_model.py            ← 품질 린터 v1.1 (FAIL 0 이 납품 조건) · confidential_scan.py(기밀 수치 유출 점검) · make_scoreboard.py
  01_모델_변수분석\                ← 모델 카드 18개(샘플 15종 + 비상장사 3개, md) + csv + 00_변수_통합카탈로그.xlsx(1,637행)
```

## 0. 시작 (매 세션)
1. 인터프리터: `python`/`py` 는 Store 스텁이라 조용히 실패한다 → `<실제 python 경로> -I -X utf8` (`-I` 는 `PYTHONIOENCODING` 을 무시하므로 `-X utf8` 필수). 스크립트는 파일로 쓰고, 한글을 heredoc/stdin 으로 넘기지 않는다. PowerShell 의 `| Select-Object -First N` 파이프는 파이썬을 죽인다.
2. 정본 `00_README_먼저읽기.md` 와 `02_설계\01_아키타입_라우팅.md` 를 읽는다. 모델을 만들기 전에 `02_레퍼런스급_품질계약.md` 1절(조항 표)을 한 번 훑는다.

## 1. 표준 흐름 (순서 고정)
**Step 0 — 확정 3가지**: 대상(회사·사업), 목적(투자검토·IC·딜·모니터링), 기준일. 질문은 **한 번에 하나**. 판단이 안 갈리는 것은 기본값으로 진행하고 보고서에 `사용한 기본값` 표를 붙인다.
**Step 1 — 라우팅**: 라우팅 문서 2절로 아키타입을 정하고 **사용자에게 한 줄로 선언**한다("V-M 으로 진행합니다: 이유"). 지원하지 않는 유형(○)은 지원하는 척하지 않는다 → 4절.
**Step 2 — 사실 수집(묻지 않고 받는다)**:
- 데이터셋이 없으면 `company-dataset-ib`(국내 `run_pipeline.py <종목>`) / `fin-data-fetch`(해외·원자료). 사용자에게 API 키를 다시 묻지 않는다.
- WACC·beta·할인율: `<WACC_기본로직>\` 의 가이드 v2 를 먼저 읽고 `run_wacc_inputs.py --only <코드> --asof <기준일>`. ERP·Size·Kd·업종 확정은 판단값(STOP 지점).
- 사용자만 줄 수 있는 것(라인별 실적·BP·계약 조건·인원 계획)은 반드시 요청한다.
**Step 3 — 입력 작성**: yaml 한 파일(엔진) 또는 해당 빌더의 입력. 모든 핵심 숫자에 출처·기준일. 사실은 단일값, 판단이 갈리는 가정은 `{base, bull, bear}` 케이스.
**Step 4 — 빌드**: `<정본>\03_엔진\build_dcf.py <inputs.yaml> <out.xlsx>`. "미사용 입력" 경고 0 까지.
**Step 5 — 3관문(하나라도 FAIL 이면 보고하지 말고 고친다)**
  ① Check: `check_dcf.py <out.xlsx> --no-sweep` (Excel 재계산, 오류 0, Checks FAIL 0)
  ② Lint: `<정본>\04_도구\lint_model.py <out.xlsx> --out <리포트.md>` (v1.1: FAIL 0, WARN 은 사유 한 줄씩. 사용자가 단일 케이스를 확정한 모델의 R09 WARN 은 의도된 구조로 기록)
  ③ 독립 재계산: 핵심 결과(EV·IRR·주당가치)를 파이썬으로 재계산해 일치 확인 + 라벨-값 점검(품질 계약 QC-18·19)
**Step 6 — 보고**: ① 결론 한 단락(주당가치·상승여력·가치 동인 1~2개) ② 케이스 표 ③ 사실 vs 판단(출처·날짜) ④ Check·Lint 결과와 WARN 별 사유 ⑤ 민감도(WACC±1%p, g±1%p 폭) ⑥ 가치를 가장 크게 흔드는 미확인 사실 최대 3개. 산출물은 xlsx + inputs.yaml + check 리포트 + lint 리포트 + 가정·변경 로그.

## 1-b. 지켜야 할 처리 규칙 (근거는 품질 계약 QC-26~33)
- **사용자가 이미 만든 부문 모델이 있으면 새로 짜지 않고 시트를 그대로 옮긴다**(행 순서·라벨·단위 보존, 값 복사·계산은 수식 재구현, 원본 대비 대조 행, 불일치는 WARN 노출). 정본 버전부터 확인한다(README·요약표는 구버전일 수 있다). 라우팅 문서 4절 V-C.
- **"간단하게/가볍게" 요청은 영향 범위(대사 깨짐·EV 영향·잃는 정보)를 숫자로 먼저 보여주고 지시를 받는다.** 임의로 정확도를 깎지 않는다.
- **검증 보고는 모든 케이스를 읽는다**(Base 만 읽고 ALL PASS 금지). 독립 재계산은 라벨 문자열이 아니라 고유 키로 셀을 찾고 찾은 개수를 단언한다.
- **사용자가 확정한 결정은 되돌리지 않는다**(단일 케이스·CB 제외·순현금 브리지 등 결정 로그). 문서가 충돌하면 최신 사실·뒤쪽 절이 이긴다.
- **기밀 입력 수치(IR 가이던스 등)는 카드·csv·문서·스킬에 옮기지 않는다.** 구조·라벨·산식만, 모델 산출값은 출처 표기와 함께 반올림. 쓴 뒤 `confidential_scan.py` 로 원본 입력 상수와 대조한다.
- **openpyxl 수식 Excel 비호환 패턴 금지**(`_xlfn.` 없는 신함수·`SUMPRODUCT(MAX(ABS()))`·`TEXT(x,"General")`·`=` 로 시작하는 라벨) — 린터 R17 이 잡는다. 사람이 손본 Cover 는 재빌드가 덮어쓴다.

## 2. 하지 않는 것 (요약 — 근거는 품질 계약 3절 결함 레지스터)
- 값 붙여넣기로 연결 끊기, 수식 안 숫자 리터럴, 입력 시트 밖의 파란 입력, `TODAY()` 시간축, 자기참조 스냅샷, 정적 시나리오표, 외부링크·고아 이름.
- 라벨과 다른 계산(EPS=영업이익/주식수, 'EBIT Margin'=매출총이익률), TV 를 기중 할인, 순부채 현금 이중차감, 터미널 무세금, 감쇠 없는 영구 성장, 손실을 `MAX(…,0)` 로 가리기.
- 목표가를 먼저 정하고 가정을 역산하기. 판단값(ERP·Size·Kd·g)을 말없이 바꾸기. 원본(사용자 파일)·엔진 원본(`<엔진 원본>`) 수정.
- 엑셀 직접 수정(수정은 yaml → 재빌드). 샘플 모델의 **값**을 입력으로 쓰기(구조·변수 정의만 참고).

## 3. 위치·규약
- 산출물: `Downloads\<YYMMDD>_<회사>_Model\` (같은 주제는 이어서). 임시물은 스크래치패드. 사용자가 폴더를 옮기면 옮긴 자리가 정본.
- 샘플 모델 카드: `01_모델_변수분석\` — 유형을 정했으면 해당 카드의 8절(질문·벤치마크·함정)과 변수표 csv 를 읽는다. 전체 변수는 `00_변수_통합카탈로그.xlsx`(아키타입 필터).
- 엔진 규칙(`03_엔진\PROJECT_INSTRUCTIONS.md`, `DCF_METHODOLOGY.md`)이 V 계열의 모델링 규칙·의심 신호·보고 형식 정본이다.

## 4. 빌더가 없는 유형 (P-RE·O-CON 분기·토큰·O-PLT 일부·X-SYN·V-XL·**V-C·V-E**·I-TAM 후보)
P-JV(채굴 JV)는 빌더가 있다: `<정본>\06_빌더_분기\run_pjv.py <inputs.yaml>`(Build→Check→Lint→독립 재계산, 가상 입력으로만 검증). V-C·V-E 는 특정 회사 전용 빌더로만 존재하고 범용 빌더가 없으며 **엔진 v2.1 로 만들 수 있다고 말하지 않는다**(3-statement·다법인 연결·순현금 Equity 브리지·`wacc`/`tv` 없는 압축형 불가).
엔진으로 억지 근사하지 않는다(라이프사이클·워터폴·월 현금흐름이 빠져 틀린 숫자가 나온다). 사용자에게 "이 유형은 전용 빌더를 먼저 만들어야 한다"고 알리고, 승인되면:
1. 해당 카드(8절 질문·벤치마크·함정, 7절 결함)와 변수표 csv 를 읽어 입력 yaml 스키마를 정한다.
2. `03_엔진\kmodel_common.py`(스타일·Cover·마스터 체크·재계산)를 import 해 같은 규약으로 빌더를 쓴다. 입력은 한 시트, 시나리오는 라이브 스위치, 분기·월 축은 시작일 하나에서 파생.
3. **독립 재계산 스크립트를 함께** 만들고 린트 FAIL 0 을 확인한다. 값은 최신 공시·시장데이터로 채운다(샘플 값 금지).
4. 완성하면 `02_설계\01_아키타입_라우팅.md` 의 도구 상태를 갱신한다.

## 5. 환경 함정
- Excel COM 재계산은 Downloads 아래에서 열기 실패하면 짧은 ASCII 경로로 복사해 처리한다. `check_dcf.py` 는 `--no-sweep`(Windows Excel 스윕 문자열 오류).
- openpyxl 로 저장하면 차트·데이터 검증(x14)·데이터테이블이 사라지므로, 사용자가 만든 기존 xlsx 를 openpyxl 로 덮어쓰지 않는다(수정이 필요하면 Excel COM 으로 입력 셀만).
- 수식에 `STDEV.S` 를 쓰면 `#NAME?` → `STDEV`(린터 R17). 라벨이 `=` 로 시작하면 수식으로 저장돼 Excel 이 파일을 거부한다. Drive(H:) 위 파일은 쓴 직후 다시 읽으면 동기화 지연으로 실패할 수 있다 → 로컬 임시 폴더에서 만들어 완성본만 복사.
- 키·토큰·비밀번호를 코드·출력·산출물에 남기지 않는다. 사용자가 채팅에 붙이면 작업보다 먼저 재발급을 알린다.
