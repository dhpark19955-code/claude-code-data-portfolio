# 기업분석 데이터셋 (IB) 표준 워크플로우

한 종목의 리서치 숫자를 **한 파일에서 신뢰할 수 있게** 보게 하는 것이 목표다. 그래서 세 가지를 지킨다:
숫자만 남긴다(줄글·모델링 제외) · 원자료와 가공을 색으로 구분한다 · 뺀 것과 빈티지를 README에 적어서 없는 걸 있는 줄 알지 않게 한다.
검증 가능한 프로젝트 사례: `<프로젝트>\` (GTF·NAVER·에이플러스에셋 3사).

## 0. 시작 전 확인

- 작업 루트는 `<프로젝트>\` (종목별 `data\<회사명_코드>\`, 공용 `scripts\`, 산출물 `마스터\`/`분석\`). 새 종목도 여기 아래에. Downloads 루트엔 **최종 배포본만** 둔다.
- 파일명이 NFD(분해형) 한글로 저장된 게 많다 → 경로는 `os.walk` + `unicodedata.normalize("NFC")`로 찾는다(`ib_dataset.Dataset.rows_of`가 이미 처리).
- 이 스킬은 사용자 레벨(`~/.claude/skills/`)에 있어 **새 세션에서도 그대로 재현**된다. 종목명+"데이터셋/정리/검증/최신본"이 나오면 자동 적용되고, 애매하면 사용자가 "데이터셋 스킬대로"라고 부르면 된다.
- **API 키는 `.env` 한 곳에 있다** — `<키 파일>` 에 `DART_API_KEY`·`KOSIS_API_KEY`(2026-09-23 저장). 스크립트는 `from env_keys import need, load_keys` 로 자동 로드하니 **사용자에게 키를 다시 묻지 말 것**. 상태 확인은 `python scripts\env_keys.py`.
  KOSIS 키는 base64라 끝의 `=` 가 필수인데 `need()` 가 빠졌으면 붙여준다. 키를 코드·출력·xlsx에 남기지 않고, 사용자가 채팅에 붙여넣으면 저장한 뒤 재발급을 권고한다. 사용자가 채팅에 키를 붙이면 **작업보다 먼저 "노출됐으니 재발급"을 알리고**, 스크립트·xlsx·출력에 절대 남기지 않는다. KOSIS 키는 끝의 `=`가 빠지면 err 11이 난다.
- 한글 경로를 bash argv로 넘기면 cp949로 깨진다 → 스크립트는 **파일명 패턴만 받아 내부에서 glob**으로 해석한다.

## 0.5 기본 진입점 — 종목명 하나로 끝까지 (`run_pipeline.py`, 2026-09-23)

사용자가 종목명만 말하면(“월덱스 데이터셋”, “101160 뽑아줘”) **먼저 이것부터 돌린다**:

```
cd "<프로젝트>\scripts"
python run_pipeline.py <종목명|코드> [--skip-fetch] [--no-docs] [--date YYMMDD]
```

0 종목 해석(corpCode) → 1 수집(DART 연결·별도 6y/10q, 네이버 5년, DART 메타·CAPEX·5%/임원·분기별 주식수, 원문 XML) → **주식수 이상치 정리(`share_utils.clean_shares`)** → 2 `fs_summary`(분기합=연간 검산) → 3 `build_base_dataset_ib.py`(README·KPI·IS 4장·컨센·비율·배당·주식수·배수·FCF·순차입금·지분구조·5%보고) → 4 Historical PER/PBR(23) + 수급 250D(70) → 5 Excel 재계산 + `dataset_audit`(Historical 밴드 이상치 포함) → 6 `Downloads\<YYMMDD>_<회사명>_Data\<YYMMDD>_<회사명>_Data.xlsx` 배포 → 7 경고·회사별 체크리스트. 로그는 `data\<종목>_<코드>\pipeline_log_<날짜>.json`.

- 소요: 수집 포함 10~15분, `--skip-fetch` 3~4분(대부분 Excel COM 재계산).
- **자동이 아닌 것**(7단계 체크리스트로 출력): 부문·제품별 매출(30번대), 오버행(33번대), 업종 KPI(60번대), IR 파싱. 원문을 읽고 판단해야 해서 회사별 스크립트로 추가한 뒤 recalc → audit → 재배포.
- exit 2 = 연간 재무 2열 미만(신규상장) → 감사보고서 파싱으로 보강 후 재실행.
- 7단계 ⚠ 경고는 무시하지 말 것: “지배주주순이익 비었는데 비지배지분은 있음” = 라벨 별칭 누락(월덱스 '…귀속될 당기순이익'에서 실제로 잡힘), “차입금 0인데 부채비율 높음” = 차입금 별칭 누락.

## 3. IB 데이터셋 빌드

엔진 `scripts\ib_dataset.py`(+`ib_style.py`)를 import 하고 종목별 `build_<종목>_dataset_ib.py`에 시트 목록만 선언한다(`build_naver_dataset_ib.py`가 참고 표본).

**시트 번호 체계**
```
00_README        데이터 사전(하이퍼링크) · 색규칙 · 제외한 것 · 데이터 빈티지·한계
01_KPI           핵심지표 — 타시트 링크(초록)+수식(검정). 성장률·마진·P×Q 등
10~13            IS/BS/CF 연결·별도 × 연간·분기 (DART 원자료, 백만원, 파랑) ← fs_sheets()
14               투자지표·컨센서스 (FnGuide 연간, 억원)
15               재무비율 — 전부 10_IS 참조 수식 ← ratio_sheet()
16~2x            현금·투자자산·배당·주식총수·밸류에이션 배수·증권사추정
30~4x            부문·비용·FCF / 산업지표(관광·GA KPI·GPUaaS 피어 등)
50~5x            지분구조·5%룰·주총·매집이력
60~6x            산업 KPI 원자료
70~7x            수급(기관·외국인, 매입평단)
```
**규칙**
- 파랑=하드코딩 원자료 / 검정=동일시트 수식 / 초록=타시트 링크. 괄호 음수, 0은 `-`, 퍼센트는 분수, 배수 `0.0x`. 병합 대신 `centerContinuous`. A열 스페이서, B열 라벨, C열부터 데이터, 격자선 off, 맑은 고딕.
- **제외**: 줄글(연혁·사업모델·컨콜 요약·논지), 밸류에이션 모델링(DCF·SOTP·민감도 — 별도 파일). 뺀 목록은 README "제외한 것" 표에.
- **단위 라벨을 의심한다**: 소스 시트 제목의 단위가 값과 다른 경우가 실제로 있었다(억원 값에 '십억원' 표기). 한 덱에 섞으면 100배 오차. 각 시트 2행에 단위를 쓰고 대표값 하나를 원자료와 대조.
- 문자열이 `=`로 시작하면 Excel이 수식으로 읽어 라벨이 사라진다(`"= 합계"` 금지).
- 저장 후 **반드시 `recalc_one.py`로 Excel COM 재계산**(openpyxl은 수식 캐시를 안 씀). 3개 이상을 한 인스턴스에서 돌리면 COM이 끊기니 종목마다 인스턴스를 분리한다.

## 4. 감사 — 숫자 리뷰를 요청받으면

`scripts\dataset_audit.py`를 먼저 돌리고(기계적 검출), 걸린 것만 원문과 대조한다.
1. **회계 항등식**: 자산=부채+자본, 자본=지배+비지배 (연결·별도 연간). 열밀림·전기오류가 여기서 잡힌다.
2. **비율 범위**: 이익률·ROE −2~2, 부채비율 0~10. OCF/영업이익은 원래 요동치니 예외.
3. **배수 시총 역산**: 20_밸류에이션의 각 행 `금액×배수`가 전부 같은 시총이어야 한다 → 10배 오류 즉시 노출.
4. **부문합↔연결 tie**: 부문 매출·영업이익·순자산 단순합과 연결(DART)을 대조. 차이가 나면 '연결조정' 행을 넣어 tie시킨다(NAVER 부문손익 열밀림, APA 부문 OP 갭이 실제 사례).
5. **단위 라벨** 대조(억/십억/백만), **지배+비지배=당기순이익**, 컨센 E열 공란의 의미.
6. 해외 peer·주가 원천은 API로 검증 불가 — "검증 못 한 범위"로 나눠 보고한다.

보고는 "안전합니다"로 끝내지 말고 **확인한 것 / 못 한 것 / 정정한 것**을 나눈다.

## 5. 정정 보존 — 가장 중요한 원칙

정정은 **데이터셋 파일에만 적용되고 소스 xlsx엔 남는** 경우가 많다. 그래서 **최신본을 뽑을 때 소스에서 재빌드하면 오류가 되살아난다.**
→ 재발행은 **감사 통과한 라이브 사본을 복사해 그 위에** 갱신분을 얹는다(`dataset_refresh_260919.py` 패턴). 소스까지 고칠 여유가 있으면 고치고, 아니면 [[dataset-audit-status]] 같은 메모에 "소스엔 오류 잔존"을 남긴다.

## 6. 갱신(최신본 재발행)

- 새 보고기간이 없으면 DART 재무는 무변동이다(3Q는 11월). API로 앵커 3개(영업수익·영업이익·순이익)만 재확인하고 넘어간다.
- 실제로 바뀌는 건 **시세**(→20_밸류에이션 배수 전부 재계산, 기준일·시총·종가를 노트에)와 **수급**. 수급 재수집은 별도 파이프라인이라 못 했으면 스냅샷 기준일을 명시한다.
- 파일명 날짜 접미사 `_YYMMDD`를 올린다.

## 7. 배포 — 완성 산출물은 **Downloads 아래 날짜폴더**에 (사용자 지정, 2026-09-22 갱신)

최종 xlsx는 `Downloads\<YYMMDD>_<회사명>_Data\<YYMMDD>_<회사명>_Data.xlsx` 로 저장한다(**폴더·파일명 규칙 2026-10-12 사용자 지정**: 예 `Downloads\261012_코리안리_Data\261012_코리안리_Data.xlsx`, 회사마다 폴더 하나)(구 규칙 `Downloads\<YYMMDD>_DATASET_IB\` 는 2026-10-12 폐지). 같은 날 여러 종목이어도 종목별 폴더로 나눈다. 루트에 바로 두지 않는다(과거엔 루트였음 — 이전 사본이 루트에 남아 있을 수 있다).
그 외 사본: 프로젝트 **마스터**(`<프로젝트>\마스터\<종목>_<코드>_DATASET_IB_<날짜>.xlsx`, 코드 포함 파일명)와, 사용자가 해당 종목 작업폴더(`Downloads\<날짜>_<주제>\...`)를 쓰고 있으면 거기에도. `SendUserFile`로도 전달.
중간 산출물(재무요약·수집 json·스크립트)은 프로젝트 `data\`·`분석\`·`scripts\`에 두고 Downloads 루트를 어지르지 않는다. 구 버전 삭제는 사용자 확인 후 휴지통으로만.
