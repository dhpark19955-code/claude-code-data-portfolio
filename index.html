사례

1. 전처리 파이프라인

공시 API 응답은 기간 기준, 부호, 단위, 계정명이 제각각이라 그대로 쓰면 틀립니다.

  • 종목명 하나로 수집부터 배포까지 8단계, 수집 포함 10~15분
  • 분기 합성, 현금흐름 부호, 단위 통일, 계정명 별칭 규칙
  • 자동으로 못 한 것은 체크리스트로 따로 출력

자세히

2. 비정형·해외 원자료

부문 매출, 사채 조건, 분기 실적 세부는 원문과 HTML 표, PDF 안에 있습니다.

  • 국내 공시 원문, 미국 XBRL, 실적발표 HTML 표, IR PDF, 홍콩 공시
  • 출처가 충돌하면 병기, 막힌 경로는 우회하지 않고 공개 대체 출처 사용

자세히

3. 검증 체계

AI가 만든 숫자는 그럴듯해서 더 위험합니다. 기계 감사와 분리된 검수를 뒀습니다.

  • 회계 항등식, 비율 범위, 배수 역산, 부문합 대조, 단위 라벨
  • 부문손익 열 밀림, 100배 단위 오류, 순차입금 누락을 실제로 잡음
  • 정정이 되살아나지 않도록 감사 통과본 위에 갱신

자세히

4. Claude Code 운영

세션이 바뀌어도 같은 품질이 나오도록 작업 환경 자체를 설계했습니다.

  • 작업 유형별 지침 라우팅, 스킬, 지휘자·일꾼·점검자 분업
  • 실패를 메모로 남겨 재발 방지, 사람이 멈추는 지점 명시
  • 다른 PC로 옮기는 설치기와 점검 도구
